# Лабораторная по ООП 4 Вариант 17


## Что было необходимо сделать.
1. Самостоятельно спроектировать контракт иерархии классов с
абстрактным базовым классом.
2. Применить виртуальные функции и динамический полиморфизм.
3. Организовать полиморфную коллекцию объектов и продумать владение
ими.
4. Использовать dynamic_cast для вызова методов, специфичных для
конкретного типа.
5. Перегрузить операторы ввода/вывода, сравнения и приведения к
числовому типу.
6. Покрыть иерархию модульными тестами и проверить отсутствие утечек
памяти


Задание
Предоставляется мини-мир — набор сущностей из одной предметной
области. Мир определяет:
• какие три конкретных класса входят в иерархию;
• какие поля хранит каждый класс;
• как вычисляется главная характеристика metric();
• какие тип-специфичные методы должны быть у конкретных классов;
• формат ввода/вывода объектов.

Что нужно спроектировать

1. Абстрактный базовый класс
Спроектируйте базовый класс, который задаёт общий интерфейс всех объектов
мира. В контракте должны быть отражены:
• назначение класса и его место в иерархии;
• виртуальный деструктор;
• не менее двух чисто виртуальных методов, общих для всех объектов
(например, вычисление метрики и печать/чтение — конкретный набор
выберите сами);
• методы, которые должны быть const, и обоснование этого;
• свободные функции operator<< и operator>>, которые делегируют
виртуальным методам печати/чтения (сами операторы не могут быть
виртуальными);
• operator double, возвращающий метрику;
• operator==, сравнивающий объекты по метрике с заданной точностью;
• политика копирования и перемещения (если она нужна базовому классу).
В отчёте объясните, почему вы выбрали именно такие сигнатуры, какие методы
сделали чисто виртуальными, а какие — виртуальными с реализацией.

2. Конкретные классы
Для каждого из трёх классов мира спроектируйте:
• набор полей и инварианты (какие значения допустимы);
• конструкторы (по умолчанию, параметризованный, при необходимости —
копирующий/перемещающий);
• реализацию metric() по формуле варианта;
• реализацию печати и чтения в согласованном формате;
• тип-специфичный метод, которого нет в базовом классе;
• const-корректность и, если нужно, override.
Тип-специфичный метод должен быть осмысленным для предметной области и
вызываться только после dynamic_cast к конкретному типу.

3. Полиморфная коллекция
Спроектируйте контейнер, который хранит объекты разных типов через указатели
на базовый класс. В контракте коллекции должны быть:
• способ добавления объекта;
• размер и обход элементов;
• вычисление суммарной метрики;
• удаление объектов и описание владения;
• выбор способа хранения: собственный динамический массив (соблюдение
правила пяти);
• гарантия, что при удалении через указатель на базовый класс вызывается
деструктор производного класса.
